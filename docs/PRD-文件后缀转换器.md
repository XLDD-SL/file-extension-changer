| 项目 | 内容 |
|---|---|
| 文档版本 | v1.0 |
| 日期 | 2026-08-29 |
| 状态 | 待评审（评审通过后进入开发） |

---

## 1. 项目概述

### 1.1 背景
用户常需要将图片文件伪装成压缩包后缀（如 `.jpg` → `.zip`），或从伪装后缀恢复原名。此类操作**仅涉及文件系统重命名**，不读取、不转换、不压缩文件内容。手动逐个改名繁琐且易错，需要一个本地批量工具。

### 1.2 核心目标
提供图形界面工具，将一个或多个文件（默认筛选 `.jpg / .jpeg / .png`，不强制）的扩展名批量改为 `.zip / .7z` 或自定义后缀，并可一键撤销。

### 1.3 非目标（明确不做）
- **不读取、不解析、不转换文件内容**：绝不 `open()` 被操作的文件本体，不调用 `shutil.move`（跨设备时会退化为复制+删除）。仅做同目录 `os.rename`。
- **不实现 OS 级文件拖拽**（见 §2 可行性 R1，标准库限制）。
- 不做文件内容校验、不做真正的压缩/解压、不做去重内容分析。
- 不做界面美化，使用系统默认主题。

## 2. 可行性分析结论

**结论：整体可行，1 项功能降级（拖拽 → 按钮添加），无阻塞性障碍。**

### 2.1 需求—技术映射

| 需求 | 实现手段（均为标准库） | 结论 |
|---|---|---|
| GUI、中文标签 | `tkinter` / `ttk` | ✅ |
| 多选文件、筛选切换 | `filedialog.askopenfilenames`，`filetypes` 双档 | ✅ |
| 拖拽到窗口 | 标准库不支持 OLE/XDND 拖放；tkinterdnd2 为第三方 | ⚠️ 降级 |
| 表格列表、多选移除 | `ttk.Treeview`（selectmode=extended） | ✅ |
| 下拉 + 自定义后缀 | `ttk.Combobox` + `ttk.Entry` + 校验 | ✅ |
| 批量重命名 + 冲突加序号 | `pathlib` + `os.rename` | ✅（R2） |
| 撤销 | 内存批次栈 | ✅ |
| 进度条 / 状态文字 | `ttk.Progressbar` + Label | ✅（R3） |
| 界面日志 + 自动滚动 | `logging` + 自定义 QueueHandler + Text | ✅ |
| 安全确认弹窗 | `messagebox.askyesno` | ✅ |
| 保存列表为 txt | `filedialog.asksaveasfilename` | ✅ |
| 帮助说明 | `tkinter.Menu` + Toplevel | ✅ |

### 2.2 风险与对策

| 编号 | 风险 | 对策 |
|---|---|---|
| R1 | 标准库 tkinter 不支持 OS 级文件拖放（Windows 需 OLE `IDropTarget`，Linux 需 XDND）；tkinterdnd2 违反零依赖约束 | 按需求备选方案**降级为"添加文件"按钮**，PRD §3.2 与验收清单同步剔除拖拽项 |
| R2 | `os.rename` 目标已存在时：**Windows 抛 `FileExistsError`，Linux 静默覆盖**——直接改名会丢数据 | 重命名前必须先生成唯一目标名（存在性探测循环），rename 后再捕获异常兜底；冲突加序号逻辑为**数据安全防线**，不可省略 |
| R3 | Tkinter 非线程安全，子线程直接操作 UI 会随机崩溃 | 重命名在工作线程执行；**所有 UI 更新**（日志、进度、列表、弹窗）经 `queue.Queue` + `root.after(100, poll)` 回主线程 |
| R4 | Windows 下文件被占用（如图片查看器锁定）时 rename 抛 `PermissionError` | 捕获并记入日志"文件被占用或权限不足"，单个失败不中断批次 |
| R5 | Linux 需额外安装 `python3-tk`；Windows 官方安装包自带 | 写入运行说明与帮助窗口 |
| R6 | 需求技术栈列出 `shutil`，但 `shutil.move` 跨设备会退化为复制+删除 | 声明：核心逻辑不使用 `shutil`；`shutil` 仅在无必要时不引入（技术栈清单以实际使用为准） |
| R7 | 中文显示依赖系统字体 | Windows 自带微软雅黑；主流 Linux 桌面均预装 Noto CJK。代码中指定 `"Microsoft YaHei"` 为首选字体并以系统默认兜底 |

## 3. 功能需求

### FR-1 界面总览
- 全部标签为中文；窗口标题"文件后缀转换器"；默认尺寸约 860×620，可调整大小，设最小尺寸 720×480。
- 自上而下四个区域：菜单栏、工具按钮区、文件列表区、操作与日志区。
- 按钮尺寸适中（内边距 ≥ 6px），布局随窗口缩放自适应。

### FR-2 添加文件
- 点击"添加文件"弹出多选对话框，默认筛选档：`图片文件 (*.jpg;*.jpeg;*.png)`；用户可切换为 `所有文件 (*.*)`。
- 允许添加任意类型文件（筛选仅是默认值，不限制来源类型）。
- 按**绝对路径去重**：重复添加同一文件时跳过并记日志"已存在，跳过"。
- 添加时即根据当前目标格式生成"新文件名预览"列。
- ~~拖拽添加~~：降级为按钮添加（R1）。

### FR-3 文件列表展示
- `ttk.Treeview` 表格，四列：`原文件路径`、`当前扩展名`、`新文件名预览`、`状态`。
- 状态列取值：`待转换` / `已转换` / `转换失败` / `已恢复`。
- 支持 Ctrl/Shift 多选；"移除选中"仅移除**未处于已转换状态**的行（已转换的行需先撤销）；"清空列表"同理，若存在已转换行，先确认对话框提示。
- 修改目标格式后，所有"待转换"行的预览列即时刷新。

### FR-4 目标格式选择
- `ttk.Combobox`（只读下拉）：`.zip`、`.7z`；旁有"自定义"输入框（`ttk.Entry`）。
- 优先级：自定义输入框非空时以其为准；为空时用下拉值。
- 自定义后缀校验（失焦或转换前触发）：
  - 自动去除首尾空白与前导 `.`；
  - 禁止空值生效（空则回退到下拉值）；
  - 禁止包含 `\ / : * ? " < > |` 及空白字符；不合法时提示框警告并拒绝生效。
- 目标后缀统一小写。

### FR-5 转换操作
1. 点击"开始转换"→ 弹出确认框（文案见 FR-8）→ 确认后执行。
2. 逐文件执行：主文件名保持不变，扩展名替换为目标后缀（无扩展名文件直接追加）。
   - 示例：`photo.jpg → photo.zip`，`image.png → image.7z`，`photo（无后缀）→ photo.zip`。
3. **冲突处理（安全防线，R2）**：目标名已存在时自动追加序号 `photo_1.zip`、`photo_2.zip`……（序号从 1 起连续探测至可用）。存在性判定采用 `os.path.exists`（天然遵循 Windows 大小写不敏感 / Linux 敏感语义）。
4. **已是目标后缀的文件跳过**：如 `photo.zip` 目标仍为 `.zip`，状态记"已是目标格式，跳过"，不重命名、不加序号。
5. 批次内部冲突同样由第 3 条实时探测天然覆盖（先改者占名，后改者得 `_1`）。
6. 执行期间：工作线程处理，UI 线程展示进度条（按成功+失败+跳过计数推进）、状态文字"正在转换 x/y"；转换期间禁用"开始转换/撤销/添加/移除/清空"按钮，结束后恢复。
7. 全部完成后弹提示框：`转换完成：成功 n 个，跳过 m 个，失败 k 个`（k=0 时不显示失败项）。
8. 转换成功的行：状态改"已转换"，"当前扩展名"更新为新后缀，预览列更新为原路径；本次所有成功项作为一个**批次**压入撤销栈。

### FR-6 恢复（撤销）功能
- "撤销上次转换"按钮：弹出批次栈**栈顶批次**，逐文件执行 `新路径 → 原路径` 的重命名。
- 撤销逐项判定：
  - 新文件不存在 → 失败，日志"撤销失败：文件不存在（可能已被移动或删除）"；
  - 原路径已被其他文件占用 → 失败，日志"撤销失败：原路径已存在同名文件，发生冲突"；
  - 成功 → 行状态改"已恢复"，"当前扩展名"还原。
- 批次内**部分成功**：成功的项从批次中移除，失败的项保留在栈顶，可再次点击重试；批次清空后弹出。
- 撤销栈无内容时按钮置灰。
- 设计决策：多次转换采用**批次栈逐级回退**（第 2 次转换 `photo.jpg→photo.zip→photo.7z` 后，第一次"撤销"回到 `.zip`，第二次回到 `.jpg`），而非一步回到最初。语义可预测，实现清晰。

### FR-7 日志与结果反馈
- 界面底部日志区（只读 `Text`，约 8 行高），每条格式：`[HH:MM:SS] [级别] 消息`。
- 使用 `logging` 模块驱动：自定义 `QueueHandler` 将日志记录发往队列，主线程取出后写入 Text（避免线程安全问题）。
- 同时写会话日志文件到系统临时目录：`%TEMP%/file_extension_changer.log`（Linux 为 `$TMPDIR` 或 `/tmp`），便于排查。
- 日志内容：添加/移除/跳过/成功/失败及原因（权限不足、文件被占用、路径不存在、目标冲突等）。
- 每条新日志自动滚动到底部（`see("end")`）。

### FR-8 安全确认
点击"开始转换"后、执行前，弹出 `askyesno` 确认框，文案固定为：
> 修改扩展名不会改变文件内容，但可能导致文件无法被原始程序打开。确定要继续吗？

用户选择"否"则中止，不产生任何文件系统变更。

### FR-9 辅助功能
- 一键清空列表（含已转换行的确认提示，见 FR-3）。
- "保存列表"：`asksaveasfilename`（默认名 `文件列表.txt`），以 `utf-8-sig` 编码写出每行 `原路径 | 当前扩展名 | 预览 | 状态`；保存成功后提示。
- "帮助"菜单：弹出 Toplevel 窗口，含运行方式、操作步骤、注意事项（含"重命名不改变文件内容"说明、Linux 需 `python3-tk`）。
- "文件"菜单：添加文件 / 保存列表 / 退出。

## 5. 关键流程

### 5.1 转换流程
```
点击开始转换
 → 确认框（FR-8） ─否→ 中止
 → 锁定按钮，清零进度
 → 工作线程逐文件：
      跳过判定（已是目标后缀）→ 记跳过
      生成唯一目标名（存在性探测循环，R2）
      os.rename(原路径, 目标名)
        成功 → 记录批次 {新路径, 原路径}，推消息给队列
        异常（FileNotFoundError/PermissionError/OSError）→ 记失败+原因
 → 线程结束，主线程：更新列表行、进度条 100%、解锁按钮、弹完成统计框
```

### 5.2 唯一目标名生成算法
```
target = stem + 目标后缀
若 target 不存在 → 返回 target
否则 i = 1,2,3,...：candidate = f"{stem}_{i}{目标后缀}"，直至不存在
```
存在性检查与 rename 之间的 TOCTOU 间隙在单用户本地工具场景下可接受；rename 时捕获 `FileExistsError/OSError` 兜底记为失败，不覆盖任何文件。

### 5.3 撤销流程
```
点击撤销上次转换
 → 取栈顶批次（含 n 项）
 → 逐项：新路径存在？原路径空闲？
      均通过 → os.rename 回原名，行状态"已恢复"，该项移出批次
      否则   → 记失败原因，该项保留
 → 批次空 → 弹出栈，更新按钮态
```

### 5.4 异常处理矩阵

| 异常 | 触发场景 | 用户可见行为 |
|---|---|---|
| `FileNotFoundError` | 原文件已被移动/删除 | 日志"路径不存在"，该文件状态"转换失败"，继续处理其余 |
| `PermissionError` | 权限不足 / Windows 下文件被占用 | 日志"权限不足或文件被占用"，状态"转换失败"，继续 |
| `FileExistsError`/`OSError` | rename 兜底（TOCTOU 或只读属性等） | 日志具体原因，状态"转换失败"，继续 |
| 自定义后缀不合法 | 含非法字符等 | 提示框警告，拒绝生效 |
| 撤销时原路径被占 | 冲突 | 日志"原路径已存在同名文件"，该项保留可重试 |

## 7. 技术设计

### 7.1 文件与模块划分（单文件 `file_extension_changer.py`）
```
① 常量与配置         确认文案、非法字符集、默认后缀列表
② 数据结构           ItemRecord（路径/扩展名/状态）、undo_stack（批次列表）
③ 核心逻辑层         unique_target_name()、rename_batch()（纯函数，不依赖 tkinter，可单测）
④ 日志层             QueueLogHandler(logging.Handler) → queue → 主线程
⑤ UI 层              class FileExtensionChangerApp（tk.Tk 子类）
                       ├ _build_menubar / _build_toolbar / _build_treeview
                       ├ _build_control_area / _build_log_area
                       ├ _add_files / _remove_selected / _clear_list / _save_list
                       ├ _start_convert（确认框→线程） / _undo_last_batch
                       └ _poll_queue（after 轮询，队列消息驱动所有 UI 更新）
⑥ 入口               main()，mainloop
```

### 7.2 线程模型
- 工作线程仅执行文件系统操作与 `logging`（QueueHandler 线程安全）。
- UI 变更（日志 Text、进度条、Treeview、messagebox）全部在主线程，由 `root.after` 每 100ms 轮询队列消费消息（类型：LOG / PROGRESS / ROW_DONE / FINISHED）。

### 7.3 关键 API
`pathlib.Path.with_suffix` / `os.rename` / `os.path.exists` / `filedialog` / `messagebox` / `ttk.Treeview` / `ttk.Progressbar` / `logging` + `queue` + `threading`。

## 10. 设计决策记录（默认决策，请评审确认）

| 编号 | 决策 | 理由 |
|---|---|---|
| D1 | 拖拽功能降级为按钮添加 | 标准库无 OS 级拖放支持，tkinterdnd2 违反零依赖约束；需求已预留此备选 |
| D2 | 允许添加任意类型文件，图片筛选仅为对话框默认值 | 工具本质是通用改名器，不应人为限制 |
| D3 | 已是目标后缀的文件"跳过"而非加序号 | `photo.zip → photo_1.zip` 语义混乱；跳过更可预期 |
| D4 | 撤销采用批次栈逐级回退（非一步回最初） | 语义可预测；如需一步回退可小幅调整 |
| D5 | 已转换行保留在列表并标记状态（不移除） | 用户可直接看到结果并撤销 |
| D6 | 会话日志默认写系统临时目录 | 不污染工作目录，便于排查；界面日志为主 |
| D7 | 核心不使用 `shutil` | `shutil.move` 跨设备会退化为复制+删除，违背"不读写内容"红线 |
| D8 | 单文件交付 | 满足"可直接运行的 .py 文件"要求 |
