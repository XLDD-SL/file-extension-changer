本文档面向想了解或参与开发的读者，梳理「文件后缀转换器」用到的具体技术、工具与技能，并对应到仓库中的核心部件与实现细节。产品需求背景见 [PRD-文件后缀转换器.md](PRD-文件后缀转换器.md)。

## 2. 架构总图与消息流

```
┌─────────────────── UI 层（仅主线程）───────────────────┐
│  FileExtensionChangerApp (tk.Tk 子类)                  │
│  菜单栏 │ 工具栏 │ Treeview 列表 │ 格式选择 │ 进度条 │ Text 日志 │
└──────────────△───────────────────────┬────────────────┘
               │ root.after(100) 轮询   │ 用户点击
               │                        ▼
┌──────────────┴──────────── queue.Queue ────────────────┐
│  消息总线（9 种消息类型：LOG / PROGRESS / ROW_OK /       │
│  ROW_SKIP / ROW_FAIL / FINISHED / UNDO_OK /             │
│  UNDO_FAIL / UNDO_FINISHED）                            │
└──────────────△───────────────────────┬────────────────┘
               │                       ▼
┌──────────────┴──── 核心逻辑层（工作线程，daemon）────────┐
│  convert_worker() / undo_worker()                       │
│  unique_target() / normalize_suffix() / preview_name()  │
└──────────────────────┬─────────────────────────────────┘
                       ▼
            文件系统（os.rename / pathlib.Path）
```

**核心约束**：Tkinter 不是线程安全的——所有 UI 操作必须发生在主线程。因此重命名在工作线程执行，结果以消息入队，主线程每 100ms 排空队列并统一刷新界面。这是本项目最重要的架构决策。

## 3. 核心部件与技术实现

### 3.1 GUI 层（`tkinter` / `ttk`）

| 部件 | 用途 | 关键实现点 |
|---|---|---|
| `tk.Tk` 子类化 | 主窗口 | `geometry`/`minsize` 控制尺寸；`protocol("WM_DELETE_WINDOW")` 拦截关闭事件（任务执行中先确认） |
| `ttk.Treeview` | 四列文件表格 | `show="headings"` 表格模式；`selectmode="extended"` 支持 Ctrl/Shift 多选；`tag_configure` 按状态给行着色；`tree.set()` 动态刷新单元格 |
| `ttk.Combobox` | 预设后缀下拉 | `state="readonly"` 防止手输；`<<ComboboxSelected>>` 事件驱动预览刷新 |
| `ttk.Entry` + 事件绑定 | 自定义后缀输入 | `<KeyRelease>` 实时刷新预览列；`<FocusOut>` 做合法性校验 |
| `ttk.Progressbar` | 转换进度 | `maximum` 设为文件总数、`value` 随消息推进（determinate 模式） |
| `tk.Text`（只读） | 操作日志区 | `state="disabled"` 锁定编辑，写入时临时切 `normal`；`see("end")` 自动滚动；超过 5000 行裁剪早期日志防止内存增长 |
| `tk.Menu` | 文件/帮助菜单 | `accelerator` 绑定 Ctrl+O；帮助内容用 Toplevel + 只读 Text 展示 |
| `filedialog` | 选文件/保存列表 | `askopenfilenames` 多选；`filetypes` 双档（图片筛选 + 所有文件）；导出用 `asksaveasfilename` |
| `messagebox` | 确认与提示 | `askyesno` 实现转换前的固定文案安全确认 |
| `ttk.Style` | 字体统一 | Windows 下全局配置微软雅黑，其他平台交给 Tk 默认字体映射 |
| DPI 感知 | 高分屏防模糊 | `ctypes.windll.shcore.SetProcessDPIAware(1)`（失败静默跳过，不影响 Linux） |

### 3.2 并发模型（正确性与体验的关键）

- **工作线程**：`threading.Thread(target=..., daemon=True)` 执行 `convert_worker` / `undo_worker`；线程内只允许「文件系统操作 + logging + 队列写入」，绝不触碰控件。
- **消息总线**：`queue.Queue` 传递 9 种元组消息（模块顶部常量定义），主线程 `after(100, poll)` 轮询消费，把日志、进度、行状态更新都收敛到主线程执行。
- **状态机锁按钮**：`_busy` 标志 + `_refresh_controls()` 集中计算所有按钮/输入框的可用性，防止任务执行中重复触发。
- **兜底防线**：线程入口包 `try/except`，意外异常时发 `FINISHED(-1)` 通知主线程弹错误框，避免界面永久锁定在"忙碌"状态。

### 3.3 文件系统层（本项目正确性的核心）

- **`pathlib.Path`**：`stem` / `suffix` / `with_name` / `exists` 处理路径，天然屏蔽 Windows `\` 与 Linux `/` 差异。
- **`os.rename` 的平台语义差异（最重要的知识点）**：
  - Windows：目标已存在 → 抛 `FileExistsError`；
  - Linux：目标已存在 → **静默覆盖**。
  - 因此 `unique_target()` 在重命名前做存在性探测循环（`photo.zip` → `photo_1.zip` → `photo_2.zip` ...），这是**防覆盖的安全防线**而非体验优化。
- **TOCTOU 兜底**：存在性检查与实际 rename 之间存在间隙，rename 外再捕获 `FileExistsError` 兜底，保证任何路径下都不覆盖文件。
- **撤销的双预检**：恢复前显式检查「新文件仍在 + 原路径空闲」，同样是为防 Linux 静默覆盖。
- **为什么不用 `shutil.move`**：跨磁盘卷时会退化为「复制 + 删除」，真正读写文件内容，违背本项目"绝不触碰内容"的红线；同目录 `os.rename` 只改目录项（NTFS 的 MFR / ext4 的 inode 引用），数据块不动，所以 1000 个文件重命名在 2 秒内完成。
- **失败原因分类**：`FileNotFoundError`（路径不存在）、`PermissionError`（权限不足/Windows 文件被占用）、`OSError`（其他系统错误）分别翻译成用户能懂的中文日志。

### 3.4 日志系统（`logging` 双通道）

- 自定义 `QueueLogHandler(logging.Handler)`：`emit()` 把格式化后的日志行放进消息队列，由主线程写入界面 `Text`——日志也因此天然线程安全。
- 文件通道：`logging.FileHandler` 写入系统临时目录（`tempfile.gettempdir() / file_extension_changer.log`），便于事后排查；两套 `Formatter`（界面只显示时分秒，文件带完整日期）。
- 日志内容覆盖：添加/去重/移除/跳过/成功/失败原因/撤销结果，与界面状态列一一对应。

### 3.5 数据结构与状态管理

- `@dataclass ItemRecord`：一条文件记录 = `iid`（Treeview 行标识）+ `initial_path`（添加时路径，对照不变）+ `current_path`（当前实际路径，转换/撤销后更新）+ `status`。
- **撤销批次栈** `List[List[dict]]`：每次转换成功的项按批次入栈（`{"iid", "old", "new"}`）；撤销时对栈顶批次逐项恢复——成功的项移出批次，失败的保留以便重试，批次清空后弹出。
- **去重**：`os.path.normcase(路径)` 作为键集合，兼容 Windows 大小写不敏感的文件系统语义。
- **五状态机**：待转换 / 已转换 / 已跳过 / 转换失败 / 已恢复；目标格式变化时，非"已转换"的行重置回"待转换"并刷新预览。

### 3.6 编码与兼容性处理（踩坑密集区）

| 场景 | 处理 |
|---|---|
| 源码中文 | 文件统一 UTF-8（`# -*- coding: utf-8 -*-` 声明） |
| 导出清单 | `utf-8-sig`（带 BOM），Windows 记事本双击不乱码 |
| PowerShell 脚本含中文 | 必须 **UTF-8 with BOM** 保存——Windows PowerShell 5.1 对无 BOM 文件按 ANSI 解析，中文会乱码 |
| bat 脚本 | 内容刻意保持纯 ASCII（中文只出现在文件名里），避开 cmd 的编码泥潭 |
| tkinter 缺失 | `import tkinter` 包 try/except，缺库时输出中文提示并等待回车退出，避免双击运行时窗口闪退 |

### 3.7 Windows 桌面集成（v1.0.1 部署方案）

- **`pythonw.exe` vs `python.exe`**：前者是同一解释器的无控制台版本，双击启动不弹黑色命令行窗口。
- **快捷方式创建**：通过 `WScript.Shell` COM 对象（PowerShell 调用）生成 `.lnk`——设置 `TargetPath`（pythonw）、`Arguments`（带引号的脚本路径）、`WorkingDirectory`、`Description`。
- **入口双文件**：`创建桌面快捷方式.bat`（纯 ASCII 的双击入口）→ 调用 `create_desktop_shortcut.ps1`（自适应 `$PSScriptRoot` 定位主程序，自动检测 Python 并优先选 pythonw，缺失时中文报错指引）。

### 3.8 版本管理与发布（Git / GitHub）

- 常规流：`git init` → 仓库级 `config user.name/email`（不污染全局）→ 提交 → `remote add origin` → 推送；分支 `main`。
- **敏感信息清除**：曾把一个误提供的字符串写进 LICENSE 与提交作者，用 `git checkout --orphan` 重建单提交历史，再 `reflog expire --expire=now --all && git gc --prune=now` 物理销毁旧对象，推送前全文检索确认零残留。
- **TLS 故障排查**：本机因 Watt Toolkit（Steam++）加速器以「hosts 改写 + 本地自签证书 MITM」方式代理 GitHub，git 自带的 OpenSSL 证书库验证失败（`unable to get local issuer certificate`）；改用 `git config http.sslBackend schannel`（走 Windows 系统证书库，其中已安装加速器根证书）后恢复。
- **发布验证**：shields.io 徽章、`raw.githubusercontent.com` 直链、服务端抓取验证 Public 可见性。

### 3.9 测试与质量保障方法

| 层级 | 方法 |
|---|---|
| 静态检查 | `python -m py_compile` |
| 核心逻辑单测 | 纯函数（后缀规整/校验/预览）+ 临时目录端到端：转换、冲突加序号（`photo.zip`/`photo_1.zip` 被占时正确得到 `photo_2.zip`）、跳过、撤销恢复、失败路径、撤销冲突防线，全部断言队列消息与磁盘实际结果 |
| GUI 冒烟 | 构造 `App` 不进 `mainloop`，直接驱动 `_handle_message` 验证状态机（批次入栈/弹出、部分失败重试、按钮启停）；用 monkeypatch 屏蔽 `messagebox` 防测试阻塞；注意 ttk 控件要用 `instate(["disabled"])` 而非 `cget("state")` 判断状态 |
| 真实窗口验证 | Win32 API（`GetWindowRect` + `CopyFromScreen`，先 `SetProcessDPIAware`）按窗口区域截屏；模拟双击（`cmd start xxx.lnk`）后用进程名+窗口标题确认启动 |

## 4. 关键设计决策速查

| 决策 | 理由 |
|---|---|
| 只用 `os.rename`，弃用 `shutil.move` | 后者跨磁盘退化为复制+删除，违背"绝不读写内容" |
| 冲突自动加序号是安全防线 | Linux 上 `os.rename` 会静默覆盖，预检查不可省略 |
| 工作线程 + 消息队列刷新 UI | Tkinter 单线程模型约束；同时避免大批量重命名时界面冻结 |
| 已是目标后缀 → 跳过 | `photo.zip → photo_1.zip` 语义混乱，跳过更可预期 |
| 撤销按批次逐级回退 | 多次转换时语义可预测，失败项可重试 |
| 界面日志走队列 Handler | 复用 `logging` 体系的同时绕开其非线程安全的 UI 写入 |
| 拖拽功能降级为按钮 | 标准库不支持 OS 级拖放，第三方 tkinterdnd2 违反零依赖约束 |
| ps1 文件保存为 UTF-8 BOM | Windows PowerShell 5.1 对无 BOM 脚本按 ANSI 解析 |
